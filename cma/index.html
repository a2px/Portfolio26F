Context

A fast-paced request-to-feature pipeline ensured customer satisfaction early on.

The core product of Locate Alpha is the Core Market Analytics software (CMA). The feature suggestion and bug reporting system was as follows: the sales team met with clients to introduce new updates and ask for feedback, which was reported to the PM, who logged these requests as tickets for the frontend developers, who pushed a change to production as quickly as possible, usually within 1–2 weeks.

The problem

Fast shipping with no design layer made the platform look like a Frankenstein of 3+ different design systems.

Constraint

Power users rely on the same repetitive workflow, meaning that any change in UI wastes their time.

Risk

Adding new features will exacerbate the overly complicated interface.

How might we

clean up this overly complicated interface without forcing power users to change their existing flow?

Solution

Understanding that a complete overhaul would be jarring for existing power users, all changes are intentionally visually conservative. Search, where every user journey starts, was left untouched.

01

Codified the design system

  • Imported all existing CSS styles into Figma, then used Claude to merge near-duplicate styles, reviewing every merge by hand
  • Ran the new design system through multiple WCAG 2.2 auditing tools and fixed the most glaring issues, with a plan for continued upkeep
  • Gave all frontend engineers the finished design file, html file, prompt, MCP server, and design.md for building new features

02

Removed clutter and added help features

  • Decluttered the menu with icon-only navigation to reduce cognitive load
  • Made client-specific features visible only to that client’s account, so other users never saw them
  • Created a help center (Docusaurus) with 24 articles and video tutorials (YouTube, Clueso) so new users could learn on their own instead of relying on sales

03

New feature notification

  • Announced new features with a one-time in-app notification, so clients beyond the requester would know they exist

Impact

A faster and more consistent way to build

The biggest impact was not a change in user experience, but a change in the flow of how new features were made. Frontend developers on a tight deadline to generate prototypes now had an extremely easy way to prototype using our existing design language.

Reflection

  • Fixing the pipeline is more important than fixing the actual design. Adding new design changes just increases the number of discrepancies in the platform. Now, engineers build on brand from the start.
  • Designing for power users means the best change is an unnoticeable one.
  • With limited access to users, I leaned on sales as a proxy and used the card sort to bridge the gap.

Next steps

01

Share the design system with developers working on other products to create a coherent branding language across multiple products.

02

03
